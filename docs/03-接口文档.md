# 智采商城｜接口文档

版本：v0.2 · 日期：2026-10-20 · 状态：拟实现合同，未接通后端；已增加商品评价接口与销售趋势数据

本文件与`05-openapi.yaml`从同一字段模型生成。标准业务接口已定义请求、返回、权限及参数约束；第三方支付/退款原始回调依赖具体服务商，已明确标注待定，不能声称已完成真实渠道对接。

## 1. 通用约定

- 本地建议地址`http://localhost:8080`，前缀`/api/v1`；部署时使用HTTPS同源反向代理。所有参数与属性名区分大小写。
- 登录返回随机Bearer令牌；请求头`Authorization: Bearer <accessToken>`。不是JWT；默认2小时，可撤销；浏览器只存内存，刷新重新登录。商城与员工登录分开。
- 业务写操作必须`Idempotency-Key`，登录、退出、渠道回调除外；重复相同请求重放原状态码与结果，同键不同请求409。幂等结果默认保存24小时，业务唯一约束长期保留。并发处理中返回409 `REQUEST_IN_PROGRESS`，带`Retry-After: 1`。
- 成功信封`{code:"OK",message:"成功",data:...,traceId:"..."}`；列表data为`{items:[],page:1,size:20,total:0}`。无内容动作返回Ack，不使用204。
- 错误信封为`{code,message,traceId,fieldErrors?}`，与HTTP状态共同使用。不要所有错误都返回HTTP 200。
- JSON未知字段拒绝；省略可选字段表示无值；不接受用null替代必填字段。PUT按请求模型整体替换允许编辑的字段，不能传状态越级修改。
- 金额均为人民币分字符串；数量为整数；ID为正整数字符串；时间UTC ISO 8601；不允许直接由客户输入订单实付、可退金额或库存余额。
- 分页page≥1，size=1–100；所有列表默认`createdAt DESC,id DESC`，分类按sort/id，库存按warehouseId/skuId；可选筛选条件未给出时不筛选。客户端不能传任意SQL排序字段。
- 资源越权：顾客不属于本人返回404；员工无接口权限403，越仓读写403；日志保留拒绝原因。
- 业务写接口在HTTP超时后结果可能已提交，先使用同键重试/按业务号查询；不得换键盲目创建第二笔。

### 1.1 错误码

| HTTP | code | 含义与客户端处理 |
|---|---|---|
| 400 | VALIDATION_ERROR / IDEMPOTENCY_KEY_REQUIRED | 展示字段错误，修正请求 |
| 401 | UNAUTHENTICATED | 重新登录，保留可恢复的草稿 |
| 403 | FORBIDDEN / WAREHOUSE_FORBIDDEN | 禁止当前操作 |
| 404 | NOT_FOUND | 不存在或不属于当前顾客 |
| 409 | IDEMPOTENCY_CONFLICT / REQUEST_IN_PROGRESS | 同键参数不一致/原请求仍执行 |
| 409 | VERSION_CONFLICT / STATE_CONFLICT | 刷新资源，不能覆盖已有变更 |
| 409 | STOCK_INSUFFICIENT / NO_SINGLE_WAREHOUSE | 缺货/没有单个仓库满足整单 |
| 409 | QUOTE_CHANGED / QUOTE_EXPIRED | 获取新报价并由顾客重新确认 |
| 409 | COUPON_UNAVAILABLE / DUPLICATE_REFERENCE | 券被占用/业务凭据重复 |
| 422 | AMOUNT_INVALID / QUANTITY_EXCEEDED / SELF_APPROVAL_FORBIDDEN | 金额、累计数量或职责分离校验失败 |
| 429 | RATE_LIMITED | 按Retry-After稍后重试 |
| 503 | DEPENDENCY_UNAVAILABLE / CHANNEL_RESULT_UNKNOWN | 状态未知，查单并以原业务号恢复 |

### 1.2 从报价到订单的示例

所有ID、令牌、金额都是演示值。请求使用HTTP语法；不是要求直接粘贴到终端执行的命令。

```http
POST /api/v1/checkout/quotes
Authorization: Bearer DEMO_TOKEN
Idempotency-Key: quote-demo-00000001
Content-Type: application/json

{"addressId":"1001","items":[{"skuId":"2001","quantity":2}],"couponId":"3001"}
```

```json
{"code":"OK","message":"成功","traceId":"demo-trace-01","data":{"id":"4001","warehouseId":"10","items":[{"skuId":"2001","productName":"机械键盘","specs":[{"name":"配色","value":"黑色"}],"quantity":2,"unitPriceMinor":"29900","grossMinor":"59800","discountMinor":"5000","payableMinor":"54800"}],"grossMinor":"59800","discountMinor":"5000","shippingMinor":"0","payableMinor":"54800","couponId":"3001","expiresAt":"2026-10-20T08:05:00Z"}}
```

```http
POST /api/v1/orders
Authorization: Bearer DEMO_TOKEN
Idempotency-Key: order-demo-00000001
Content-Type: application/json

{"quoteId":"4001","remark":"工作日收货"}
```

返回201及ResultOrder，state为UNPAID。若价格/券/仓库不再符合报价，返回409，不创建订单。

### 1.3 分批入库示例

```http
POST /api/v1/admin/purchase-receipts
Authorization: Bearer DEMO_WAREHOUSE_TOKEN
Idempotency-Key: receipt-demo-000001
Content-Type: application/json

{"purchaseId":"5001","deliveryReference":"DELIVERY-20261020-01","items":[{"purchaseItemId":"5002","quantity":60}]}
```

供应商送货单业务唯一；同请求重试返回原收货单；换键但使用相同送货单引用时返回已有结果或409 DUPLICATE_REFERENCE，不能再入库。

### 1.4 售后与退款调用顺序

顾客创建售后→客服review→退货类型由顾客return-shipment→仓管receive→财务创建refund→查询退款状态。发货前取消跳过退货物流与收货。退款金额只能服务端计算。

## 2. 接口目录与约束

下文的返回模型是data类型；列表返回对应模型的分页。每个字段的必填性、类型、枚举与校验位于第3节及OpenAPI。201表示资源创建，202表示异步任务受理，200表示本次本地操作完成；均不替代支付/退款业务终态。

## 3. 字段字典

金额、ID、时间、状态等共享类型先列出；响应信封和分页模型也包含在OpenAPI中。所有请求中的跨字段规则同时参照需求文档。

### Id

类型：`string`。正整数字符串；数据库BIGINT主键，禁止前端转换为Number pattern=^[1-9][0-9]{0,18}$

类型：`string`。人民币分，非负整数字符串；Java long运算并检查溢出 pattern=^(0 / [1-9][0-9]{0,17})$

### Quantity

## 5. 契约变更流程

先修改需求与状态决策→同步OpenAPI和本文→更新后端DTO及校验→更新前端类型与调用→执行契约和集成检查。字段重命名、状态删除、权限扩大均属于显式变更。不得通过返回任意Map或放宽additionalProperties绕过合同。


## 4. v1.0补充：商品评分与评价 API

以下接口将基础商品评分与评价纳入v1.0范围，与`05-openapi.yaml`同步。评价内容默认先审核，只有`PUBLISHED`评价对外可见并计入评分汇总。

**op132 · 查询商品公开评价**

`GET /api/v1/catalog/products/{id}/reviews`

- 权限：公开；请求体：无；返回：`PageReview`；成功HTTP：200。
- 查询参数：`page`（可选，默认1）、`size`（可选，默认20，最大100）、`rating`（可选，1–5）。
- 规则：只返回`PUBLISHED`评价；顾客展示名脱敏；默认按创建时间倒序。商品详情可用，商品列表只显示商品接口中的评分均值和评价数。

**op133 · 为已完成订单商品提交评价**

`POST /api/v1/orders/{id}/reviews`

- 权限：`CUSTOMER`；幂等键：必填；请求体：`ReviewCreate`；返回：`Review`；成功HTTP：201。
- 规则：订单必须属于当前顾客且状态为`COMPLETED`；`orderItemId`必须属于该订单；每个订单明细最多一条评价。评分为1–5；文字可选，最多2000字符；图片最多5张。新评价进入`PENDING`，不立即公开或计入评分。

**op134 · 查询我的评价**

`GET /api/v1/account/reviews`

- 权限：`CUSTOMER`；请求体：无；返回：`PageReview`；成功HTTP：200。
- 查询参数：`page`、`size`。只返回当前顾客自己的评价，包括待审核、已公开和已驳回状态。

**op135 · 修改被驳回的评价并重提**

`PUT /api/v1/account/reviews/{id}`

- 权限：`CUSTOMER`；幂等键：必填；请求体：`ReviewUpdate`；返回：`Review`；成功HTTP：200。
- 规则：仅原作者可修改自己处于`REJECTED`的评价；提交后回到`PENDING`；使用`version`做乐观锁校验。已公开评价不能通过此接口静默改写评分汇总。

**op136 · 后台评价列表**

`GET /api/v1/admin/reviews`

- 权限：`review:read`；请求体：无；返回：`PageReview`；成功HTTP：200。
- 查询参数：`page`、`size`、`state`、`rating`、`productId`、`keyword`均可选。
- 规则：按员工权限返回评价；默认按创建时间倒序；后台列表展示必要的脱敏顾客信息，不返回认证凭据或无关个人信息。

**op137 · 审核商品评价**

`POST /api/v1/admin/reviews/{id}/moderation`

- 权限：`review:moderate`；幂等键：必填；请求体：`ReviewModerationRequest`；返回：`Review`；成功HTTP：200。
- 规则：`action=APPROVE`将待审核评价变为`PUBLISHED`；`action=REJECT`变为`REJECTED`且必须填写原因。只有公开状态变化会影响商品评分均值与评价数量；审核记录写入审计日志。

## 5. v0.2字段与模型补充

- `Product`增加`ratingAverage`（0–5，保留两位小数；没有公开评价时为0）和`ratingCount`（公开评价数量）。首页可以忽略这些字段；商品列表可展示摘要。
- `SalesReport`增加`trend[]`。每个趋势点包含`periodStart`、`receiptMinor`、`refundMinor`、`netReceiptMinor`和`paidOrderCount`。`periodStart`按`granularity`返回日期区间起点。
- `Review`包含评价ID、商品ID/名称、脱敏顾客展示名、星级、文字、图片资源、审核状态、创建时间和版本；审核原因与公开时间按权限/状态返回。
- 评价创建与重提均使用幂等键；每个订单明细唯一约束是最终防重手段，不能只依赖前端禁用按钮。
